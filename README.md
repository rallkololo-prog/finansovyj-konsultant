# Куда уходят деньги по выпискам Т-Банка и Сбера

Локальное веб-приложение, которое читает банковские выписки, разбирает их на операции и показывает не статистику,
а разбор финансовых привычек: где уходят деньги, что можно сократить и сколько это даст в деньгах.

В выписках **два банка**: Т-Банк (карта 3255, с 2 октября 2020) и Сбер (карта 7346, с 23 ноября 2022).
В шапке приложения есть переключатель источника: «Оба банка» / «Т-Банк» / «Сбер» — все цифры пересчитываются.

Открыть: `app/index.html` (двойной клик, работает по `file://`, интернет и сервер не нужны).

## Загрузить свою выписку

Приложение автономное: **PDF разбирается прямо в браузере**, файл никуда не отправляется, сервер не нужен.

1. Открыть `app/index.html` — без загруженных данных приложение сразу показывает раздел «Загрузить выписку».
2. Перетащить PDF в рамку (или нажать «Выбрать PDF»).
3. Через пару секунд страница пересчитается: 3 834 операции Т-Банка разбираются примерно за 0,8 с, 7 890 операций
   Сбера — за 0,9 с.

Что разбирается на стороне браузера: `pdfread.js` (чтение PDF и текста с координатами, включая сжатые объекты
и объектные потоки), `classify.js` (правила категорий и брендов), `import.js` (сборка операций Т-Банка и Сбера
и нормализация в формат приложения), `bootstrap.js` (подмена демо-данных загруженными при старте).

Особенности:

- Поддерживаются **только два банка: Т-Банк** («Справка о движении средств») и **Сбер** («Выписка по счёту дебетовой
  карты»). Нужны PDF с текстовым слоем: сканы и фотографии не подойдут.
- Выписку другого банка приложение отклонит с понятным сообщением («Это выписка другого банка. Сейчас поддерживаются
  только Т-Банк и Сбер») — а не станет разбирать наугад. Если файл прочитан, но операций не нашлось, будет второе
  сообщение об этом. На экране загрузки поддержка двух банков показана плашками «Т-Банк», «Сбер» и «другие банки — пока нет».
- Если загрузить второй банк, операции **объединяются** (в шапке появятся оба источника), переводы между своими
  картами останутся переводами и не станут расходом.
- Загруженные данные лежат в `localStorage` браузера (`fin.dataset.v1`), кнопка «Вернуть демо-данные» их удаляет.
- Категории ставятся теми же эвристиками, что в демо: по названию магазина, а не по составу чека. Словарь —
  около 130 шаблонов: сети (Магнит, ВкусВилл, Лента, Шоколадница, Rostic's…), сервисы (Netflix, Spotify, Яндекс Плюс)
  и общие отраслевые слова (шиномонтаж, фитнес, барбершоп, стройматериалы, зоомагазин, книжный, Теле2).
  Ошибки можно поправить вручную на странице «Непонятные траты» — правки сохраняются отдельно и переживают перезагрузку.
- Чего словарь не знает, то честно попадает в «Прочее» и показывается отдельной страницей, а не растворяется
  в отчётах: одна минута выбора категорий — и все цифры пересчитываются под конкретного человека.

отправить сам `.html` или `.zip`: результат тот же, предупреждений меньше.

Внутри `.exe` лежит та же пустая версия (без ваших данных): программа только распаковывает страницу
в `%TEMP%\fin-konsultant` и открывает её в браузере по умолчанию.

Собрать заново: `node tools/build.js`, затем компиляция оболочки (нужен только встроенный в Windows
`csc.exe`, .NET SDK не требуется):

## Данные

Два PDF без текстового слоя (оба сгенерированы OpenPDF/JasperReports, поэтому парсер общий):

| Источник | Файл | Период | Операций | Сверка с итогами выписки |
|---|---|---|---|---|
| Т-Банк, карта 3255 | `Dokument.pdf`, 153 стр. | 02.10.2020 — 23.11.2026 | 3 834 | остаток 49 211,98 ₽; пополнения 7 546 702,59 ₽; расходы 7 497 490,61 ₽ — до копейки |
| Сбер, карта 7346 | `Vypiska_po_sche_776_...pdf`, 327 стр. | 23.11.2022 — 23.11.2026 | 7 890 | пополнения 6 874 224,13 ₽; списания 6 842 967,65 ₽ — до копейки |

**Как проверяется «без ошибок»:** суммы всех разобранных операций сравниваются с итогами, напечатанными
в самой выписке. Оба файла сошлись до копейки. Дополнительно: расходы при переключателе «Оба банка»
равны ровно сумме расходов каждого банка (1 662 667 + 3 587 023 = 5 249 690 ₽) — то есть ни одна
операция не посчитана дважды.

**Переводы между своими картами** (Сбер → Т-Банк и обратно) попадают в обе выписки, поэтому они
классифицируются как переводы, а не покупки, и в расходы не входят вовсе — иначе суммы удвоились бы.

В PDF нет текстового слоя, поэтому всё извлечено самописным парсером на стандартной библиотеке
(сеть до PyPI в этом окружении недоступна, `pdftotext`/`qpdf` не установлены).

### Конвейер

| Шаг | Файл | Что делает |
|---|---|---|
| 1 | `pdf_extract.py` | парсит PDF: объекты, `/Pages`, ToUnicode CMap, шрифтовые ширины, матрицы `Tm/Tlm` → `dokument.txt` |
| 2 | `pdf_runs.py` | выдаёт позиционированные текстовые руны (x, y, текст) → `runs.json` (44 935 рунов) |
| 3 | `parse_tx.py` | группирует руны по строкам и колонкам → `transactions.json` (3 834 операции) |
| 4 | `classify.py` | тип операции + категория + бренд + мерчант → `tx_classified.json` |
| 4a | `pdf_runs.py` + `parse_sber.py` | то же для выписки Сбера: у неё другая сетка колонок (дата · время · категория · сумма, вторая строка — дата обработки · код · описание) → `sber_transactions.json` |
| 4b | `classify_sber.py` | категории Сбера («Супермаркеты», «Рестораны и кафе»…) + мои regex-правила → `sber_classified.json` |
| 5 | `build_data.py` | объединяет два источника (`src` у каждой операции), считает агрегаты → `app/data/data.js` |

Пересборка после правок:

```powershell
$env:PYTHONIOENCODING="utf-8"
python classify.py
python classify_sber.py   # если менялись категории Сбера
python build_data.py      # печатает: ok <размер>
```

## Периоды

- **Активный** (по умолчанию): 1 февраля — 23 ноября 2026, 296 дней. Именно здесь обе карты работали одновременно.
- **Полный**: 2 октября 2020 — 23 ноября 2026, 2 244 дня.
- Любой свой период задаётся календарём в шапке, а конкретный год — списком «год…» рядом с пресетами; пересчёт идёт в браузере (`app/engine.js`), без сервера.
- Все годы есть в данных всегда: 2020 — 0 ₽ (1 покупка), 2021 — 6 745 ₽, 2022 — 166 838 ₽, 2023 — 796 808 ₽, 2024 — 1 254 901 ₽, 2025 — 1 495 698 ₽, 2026 (по 23 ноября) — 1 528 700 ₽.

Роли карт менялись: в 2025 году через Сбер прошло 1 299 322 ₽ против 196 376 ₽ по Т-Банку,
а в 2026-м — 1 342 408 ₽ по Т-Банку против 186 293 ₽ по Сберу. Поэтому выводы про «пятилетнюю историю»
имеют смысл только с переключателем «Оба банка».

## Планирование (не связано с выпиской)

Разделы, где данные вводите вы; всё хранится в браузере (`localStorage`) и никуда не отправляется.

| Раздел | Что делает |
|---|---|
| «Мои данные» | Все виды дохода (каждый месяц или разово) и обязательные ежемесячные расходы — вручную, списком, можно добавлять и удалять строки. Сверху считается доход в месяц, расходы в месяц и **свободно в месяц** = доходы − обязательные расходы. Это число по умолчанию подставляется в «Накопления». |
| «Разделить счёт» | Кто кому сколько должен за общий счёт: общая сумма делится на всех поровну, каждый сравнивается со своей долей, итоговые переводы сводятся к минимуму (алгоритм «самому большому долгу — самому большому кредиту»). Если общая сумма больше, чем внесли, отдельно показывается, кто ещё должен доплатить в общий котёл. |
| «Накопления» | Список целей: название, цена, сколько уже отложено, дата (необязательно). Темп берётся из «Мои данные» (свободно в месяц), но его можно переопределить своим числом. Если задана сумма в месяц — считается дата достижения. Если задана дата — наоборот, сколько нужно откладывать в месяц. Прогресс показывается полосой; проценты и инфляция не считаются. |

## Важное про данные

Настоящая история трат по этой карте начинается с февраля 2026 года: до этого карта почти
не использовалась для покупок (за 2020–2025 всего 584 покупки — траты шли через карты других банков,
а здесь были вклады, брокерский счёт и переводы).

Поэтому в приложении два периода:

- **Активный** (1 февраля — 23 ноября 2026, 296 дней): 1 318 752 ₽, 2 067 покупок, 135 607 ₽/мес.
  Привычки, рекомендации и сценарии считаются по нему.
- **Весь** (2 октября 2020 — 23 ноября 2026, 2 244 дня): 1 662 667 ₽, 2 651 покупка.
  Нужен, чтобы показать пятилетний контекст и инвестиции/переводы.

Все суммы «за 5 лет» — арифметическая экстраполяция текущего темпа (месяц × 60), а не факт.
В интерфейсе это написано прямым текстом в каждом таком месте.

## Что считается расходом

Переводы между своими счетами, пополнения вкладов и брокерского счёта, снятие наличных,
возвраты и кэшбэк **не считаются расходами** — иначе картина удваивается. Отдельно показаны
инвестиции и переводы людям, но вне потребительских категорий.

## Разделы

- **Обзор** — ключевые цифры, месячная динамика, структура расходов, автоматические находки.
- **Что можно улучшить** — 11 рекомендаций, отсортированных по приоритету, каждая с цифрами,
  основанием, достоверностью и ссылкой на конкретные операции.
- **А что, если бы я экономил** — калькулятор: категории, процент (5/10/15/20/30 или свой),
  экономия за месяц, год, 5 лет и график накопления.
- **Финансовые привычки** — дни недели, часы, месяцы, рост категорий, что стало появляться чаще,
  сравнение по годам.
- **Самые дорогие привычки** — рейтинг категорий и брендов, мелкие покупки, сравнение магазинов
  внутри одной категории.
- **Регулярные списания** — 18 групп с оценкой периодичности и честной пометкой
  «кандидат на проверку» (выписка не знает, пользуетесь ли вы сервисом).
- **Аномалии** — крупные разовые операции, повторные суммы, всплески месяцев, комиссии.
- **Отчёт за месяц** — доходы, расходы, категории, компании, что выросло и упало, рекомендации.
- **Финансовый профиль** — регулярные против переменных, концентрация, стабильность.
- **Стриминги и подписки** — только цифровые сервисы: Яндекс Плюс, VK, Aéza, игровые платформы,
  и отдельно связь. Внутри Яндекс Плюса разложено, что было автопродлением (100 ₽ × 8), а что —
  разовыми покупками фильмов.
- **Непонятные траты** — компании, которые не удалось уверенно отнести к категории. Для ООО и ИП
  подтянута справка по ИНН/ОГРНИП (вид деятельности из ЕГРИП, сайт, 2ГИС) со ссылкой на источник.
  Категорию можно поставить вручную: подсказки-чипы или выпадающий список со всеми категориями.
  Кнопка «Показать операции» открывает все платежи этой компании с датами и суммами за выбранный период.
  Выбор сохраняется в браузере и сразу пересчитывает всю статистику.
- **Операции** — журнал всех операций: поиск, фильтры по категории, магазину, сумме, банку
  и типу (покупки / переводы / всё), сортировка по сумме.

## Период

В шапке — пресеты (активный, этот месяц, прошлый, 3 месяца, 2026, 2025, всё) и два календаря
«с / по»: можно выбрать любой диапазон, вплоть до одного дня. Все цифры, рекомендации, сценарии
и графики пересчитываются на клиенте под выбранные даты (движок `app/engine.js` — порт
`build_block()` с Python, сверен с ним до копейки). На периоде короче двух недель выводы о привычках
намеренно не делаются: по одной-двум покупкам закономерность не определяется.

Ноябрь 2026 отмечен как неполный: он оборван 23-м числом.

## Ограничения

- Категория определяется по названию магазина, а не по составу чека: «Продукты» — это покупки
  в продуктовых, а не гарантия, что там не купили стиральный порошок.
- 15,7% расходов остались в «Прочем» (ИП, переводы физлицам, нераспознанные названия) — они
  показаны отдельно, а на странице «Непонятные траты» их можно разметить вручную.
- Ставки на спорт отмечены как прекращённые (последнее списание 23.08.2026) и исключены из
  потенциала экономии: экономить на том, что уже закончилось, нельзя.
- Подписки и «подозрительные» списания — кандидаты на проверку, а не обвинения.
- Ноябрь 2026 оборван 23-м числом, октябрь 2020 — 2-м: эти месяцы помечены как неполные
  и не участвуют в сравнениях как полные.
- При загрузке своего PDF баланс на конец периода неизвестен: в выписке разных банков он может
  отсутствовать или считаться по-своему, поэтому сверка «остаток = сумма операций» делается только
  для тех форматов, где он есть. Итоговые суммы по загруженным операциям считаются из самих операций.
- Работает в актуальных Chrome, Edge, Firefox и Safari (нужны `DecompressionStream` и `localStorage`).
  В очень старых браузерах разбор PDF не запустится — приложение покажет ошибку чтения файла.

## Мобильная версия

Оба HTML-файла адаптированы под телефон — отдельная сборка не нужна, вёрстка переключается сама.

- **Перелом 720 px.** Уже — мобильный режим, шире — прежний вид с боковым меню.
- **Навигация.** Боковое меню скрывается, вместо него внизу панель из пяти кнопок (Обзор, Советы, Привычки, Операции, Ещё) с бейджами; «Ещё» открывает шторку со всеми разделами и сведениями о выписках.
- **Таблицы становятся карточками.** Заголовки столбцов переносятся в подписи ячеек на лету (`labelTables` в `app.js`), поэтому разметку 24 таблиц править не пришлось. Длинные описания (как в журнале операций) идут отдельной строкой, а не в тесную колонку.
- **Графики.** SVG имеет viewBox 760 px; на узком экране шрифт подписей увеличен, иначе он сжимался до нечитаемых 5 px.
- **Период.** Пресеты прокручиваются горизонтально, оба календаря растянуты на всю ширину, диапазон подписан под ними.
- **Модальное окно** на телефоне занимает весь экран (высота `100dvh`, чтобы не мешала адресная строка).
- **Поворот экрана** обрабатывается: при смене ширины страница перерисовывается без перезагрузки.

Проверено на ширине 375 px (iPhone SE/13): все 16 разделов, отсутствие горизонтальной прокрутки, карточки операций, шторка, календарь и графики.

## Миниприложение (PWA) и VK

Приложение можно поставить на телефон как обычное: иконка на главном экране, запуск без адресной строки, работа без интернета. Для этого в `app/` добавлены `manifest.webmanifest`, `sw.js`, `pwa.js` и три иконки (`icon-192.png`, `icon-512.png`, `icon-maskable-512.png`), а сборщик складывает готовую папку для хостинга.

**Что появляется:**
- иконка «Финансы» и название на главном экране;
- офлайн-режим: service worker кэширует оболочку, приложение открывается без сети;
- кнопка «Установить на телефон» — показывается, когда браузер готов к установке (Android/Chrome, десктопный Chrome);
- на iPhone установка вручную: «Поделиться» → «На экран Домой».

**Где взять файлы.** `node tools/build.js` создаёт две папки:
- `dist/site-dlya-vseh/` — пустая версия для публикации (6 файлов: `index.html`, `manifest.webmanifest`, `sw.js`, три иконки);
- `dist/site-personal/` — то же, но с вашими данными. **Публиковать нельзя.**

**Как выложить (GitHub Pages):**
1. Создать репозиторий, положить туда содержимое `dist/site-dlya-vseh/`.
2. Settings → Pages → Source: «Deploy from a branch», branch `main`, папка `/ (root)`.
3. Через минуту адрес вида `https://<логин>.github.io/<репозиторий>/` — открыть на телефоне и установить.

Альтернатива без Git: перетащить папку на app.netlify.com/drop — адрес появится сразу.

**Как выложить в VK (мини-приложение):**
1. Выложить `dist/site-dlya-vseh/` на любой https-хостинг (тот же GitHub Pages).
2. vk.com/apps → «Создать» → тип «Мини-приложение (Web)» → указать адрес.
3. Заполнить название, иконку (возьмите `icon-512.png`), описание — и опубликовать.

Приложение уже умеет работать внутри iframe (класс `embedded`: убирает нижние отступы, сообщает Telegram о готовности). Данные пользователя в VK хранятся в его браузере — на сервере ничего нет.

**Важно про данные:**
- хранилище привязано к адресу сайта: после переезда на https старая история не переносится;
- для переноса есть «Загрузить выписку» → «Сохранить данные в файл» (JSON) и «Загрузить файл данных» — туда попадают операции, уточнения категорий, доходы, разделение счёта и цели;
- iOS может очистить хранилище после недели без использования — файл JSON это лечит;
- если localStorage недоступен (приватный режим, некоторые webview), приложение переключается на память и продолжает работать, просто не сохраняет.

**Обновление версии.** После изменений поднимите `VERSION` в `app/sw.js` (например `fin-2026-12-01-1`) и пересоберите — иначе телефон останется на закэшированной старой копии.

## Хостинг и обновления

**Где живёт.** Публичная версия — статический сайт на GitHub Pages: репозиторий хранит только код
и пустую сборку, персональных данных там нет. Приложение устанавливается с адреса как PWA
(Chrome/Android) или добавляется на домашний экран (Safari/iOS).

**Как приходят обновления.**

1. Правите код → `node tools/build.js` → коммит и `git push`.
2. GitHub Pages публикует новую версию сам, в течение минуты.
3. У людей приложение проверяет обновление при запуске и при возврате на вкладку
   (не чаще раза в 30 минут). Если версия новее — внизу появляется плашка
   «Вышла новая версия приложения» с кнопками «Обновить» и «Позже».
4. «Обновить» → новый service worker активируется, страница перезагружается, старый кэш удаляется.

**Обязательное правило:** после каждой правки поднимайте `VERSION` в `app/sw.js`
(например `fin-2026-11-23-3`). Без этого браузер считает кэш актуальным и обновление не увидит.

**Кому отправляете файл.** Однофайловая HTML-версия обновляется только пересылкой нового файла —
сама она из интернета ничего не подтягивает. Поэтому удобнее давать людям адрес, а не файл.

**Проверено локально** (`python -m http.server` по папке `dist/site-dlya-vseh`): манифест отдаётся,
service worker встаёт, приложение открывается без сервера, плашка обновления появляется после
поднятия `VERSION`, кнопка «Обновить» перезагружает страницу и удаляет старый кэш.

## Если появятся платные функции

Код готов к включению, интерфейса оплаты пока нет — и это сознательно: пустые кнопки
на модерации выглядят как недоделка.

Что уже сделано:

- `app/vk.js` определяет платформу запуска (`window.VKCTX.platform`, `isMobileApp`, `isIOS`);
- `app/app.js`, блок `PRO` (`enabled`, `trialDays`, `priceLabel`) и функция `canSell()` —
  единственное место, где решается, можно ли показывать оплату. На iOS и Android она вернёт `false`.

Что нужно сделать при включении:

1. **Сервер.** Подтверждение оплаты VK Pay проверяется только на сервере (п. 1.2.8) —
   клиентская проверка запрещена. Сервер хранит только факт оплаты и срок подписки.
2. **Документы.** В `PRIVACY.md` добавить раздел про платёжные данные, в `TERMS.md` —
   состав платных функций, цены и порядок возврата (раздел уже есть, его надо заполнить).
3. **Интерфейс.** Кнопку оплаты выводить только при `canSell()`; на мобильных платформах
   ВК её не показывать вообще (п. 5.4.1).
4. **Пробный период.** Если основная функциональность станет платной, нужен триал
   (п. 5.4.3) — поле `PRO.trialDays`.
5. **Свободный уровень.** Загрузка выписки и обзор должны остаться бесплатными,
   иначе приложение отклонят.
6. **Проверка.** Прогнать оба сценария в ВК: веб-версия и мобильное приложение —
   во втором оплаты быть не должно.
